About

A bench for taking algorithms apart.

ML Bench is one HTML file. It loads your tables, fits nine algorithms to them, and shows you what each one learned, what it got wrong, and where it is quietly lying to you.

Carol Mello
Data engineer · builder of ML Bench
Why I built it

I wanted to see the algorithm move.

Most explanations of machine learning are either a paragraph of intuition with no numbers behind it, or a notebook you have to install four things to run. Neither lets you poke at the thing. I wanted a page where you load a table, pick a model, change one setting, and watch the result move — and where the page is honest with you when the result is nonsense.

I could not find one that was both open in a browser tab and straight about its own numbers. So I built it.

The technical foundation comes from my work in data engineering. The subject comes from years of building data analytics visualisations.

That combination is the whole design brief. A data engineer's instinct is that the pipeline is where things break: the split that leaks, the column scaled after the split, the median imputed from rows the model should never have seen. A visualisation habit says the number is not the finding — the residual plot is. ML Bench is built around both.

What you can do with it

Four things, in order.

The workflow across the top of the app follows the same sequence.

Load

Bring your own tables

Drop in CSV, TSV or JSON. Column types, ranges, missing counts and correlations are profiled on arrival. Several tables can sit side by side, and scenarios can point at different ones.

Fit

Nine algorithms, one form

Regression, classification and clustering, each with the hyperparameters that actually matter exposed. Run one configuration, or fire the whole family at defaults for a first read.

Read

Diagnostics, not just a score

Predicted-versus-actual, residuals, confusion matrices, ROC curves, permutation importance, coefficients or tree rules. Every run is kept so you can compare what changed.

Report

A PDF you can hand over

Data profile, every scenario with its configuration and metrics, charts, findings, and an appendix listing what the analysis cannot support. Built in the browser, saved to your machine.

Under the hood

No ML library. That is the point.

Every model is implemented in plain JavaScript inside the page, so what you read is what runs.

  • Linear & ridgeSolved by normal equations with partial-pivot Gaussian elimination; the intercept is left unpenalised.
  • LogisticBatch gradient descent with L2, one-vs-rest for more than two classes.
  • TreesCART with an exact sweep over sorted feature values — gini for classes, squared error for numbers.
  • Forests & boostingBootstrap aggregation with feature subsampling; gradient boosting fits shallow trees to the running residuals.
  • k-NN & naive BayesBrute-force Euclidean neighbours, and Gaussian likelihoods per class.
  • k-meansk-means++ seeding, best of several restarts, with silhouette and an elbow curve for choosing k.
  • PipelineImputation, standardisation and encoding statistics are fitted on the training rows only, then applied unchanged to the held-out rows. This is the part most demos get wrong.
  • ImportancePermutation importance, so the same measure works for every model — including the ones with no coefficients.

Limits

What it is not.

Stated here rather than discovered later.

not a forecaster

A fitted model gives point predictions, not forecasts. There is no ARIMA, no seasonality, no confidence interval. For dated series, use a time-series tool.

not causal

Feature importance shows what the model leaned on, not what drives the outcome. Moving an input in the world will not necessarily move the result the way a sweep chart suggests.

not deep learning

No neural networks, no text or image models. Tabular data, classical algorithms, honestly evaluated.

single-threaded

Everything runs on the page's main thread. A forest on tens of thousands of rows will lock the tab for a while — the setup screen estimates the cost before you start.

no tuning search

Comparisons are between the configurations you ran, not between algorithms at their best. A grid search would change the ranking.

private by default

Your data is read in the browser and never leaves it. There is no server, no account, no upload. Close the tab and the session is gone.
